# E.Leclerc Drive requests (captured on the site, 2026)

Reference pages: `test/fixtures/leclerc/` (regenerated by `npm run fixtures -- leclerc`).
Initial knowledge of the calls comes from the MIT project
[skunkobi/mcp-leclerc-drive](https://github.com/skunkobi/mcp-leclerc-drive), checked again and extended.

Every request goes through the user's browser session (`credentials: include`) from a tab of the site. The site is
protected by DataDome: requests go one by one, spaced out (1 s by default), and a block stops everything
(`SiteBlockedError`); it is never retried.

## Store and URL

- Store-specific shopping host: `fdN-courses.leclercdrive.fr` (N varies: fd3, fd4, fd14…).
- Path: `/magasin-<noPL>-<noPR>/…`. `noPL` = delivery point, `noPR` = pickup point (equal for a drive, different
  for a walk-in pickup point). The name suffix of the site's URLs (`-<Store-Name>`) is cosmetic.
- The session is bound to the drive opened on the site: after `set_store`, if pages answer "session expirée", the
  user opens the new store on leclercdrive.fr.

## Page data: widgets

The ASP.NET pages pass their data to widgets as JSON:
`Utilitaires.widget.initOptions('<ASP.NET id>', {…});`. A widget is read by the end of its identifier:

| Widget (suffix)       | Content                                                                                                                      |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `_pnlCartouchePanier` | current cart (`objCartouchePanier.lstElements[].lstEnfants[].objElement`, `sType: Panier`) — **present on every store page** |
| `_pnlElementProduit`  | search results (`objContenu.lstElements[].objElement`, `sType: Produit`)                                                     |
| `_pnlBlocsFiltres`    | `iNbTotalProduits`, reported total                                                                                           |
| `_pnlFicheProduit`    | product page (`objProduit`)                                                                                                  |

A missing `_pnlCartouchePanier` means the page is not a store page: DataDome interstitial (HTTP 200 or 403) or
"session expirée". The `x-datadome` header and the DataDome script are present on real pages too: they do not
detect a block.

## Search

- `GET /magasin-…/recherche.aspx?TexteRecherche=<term>`: **all** results at once (no pagination).
- No result: no `_pnlElementProduit` widget (the site shows suggestions, ignored).
- Product: `iIdProduit`, `sLibelleLigne1` + `sLibelleLigne2` (HTML entities), `nrPVUnitaireTTC` (decimal euros),
  `nrPVParUniteDeMesureTTC` + `sUniteMesureTotale` (`kg`, `l`, `p` = piece; `mt` ignored), `iQteDisponible`.
- Promotions:
  - immediate discount (BRII): `fEstBRIIActifEtDisponible`, `nrPVBRIIDeduit` (price paid), `nrPVMesureBRIIDeduit`,
    `sTexteLogoBRII` ("Avantage immédiat de 30%");
  - multibuy: `fEstBRIIActifEtDisponible` without a deducted price, `eIncitationLot`, `sTexteLogoBRII`
    ("Le 2ème article à -40% (le moins cher des 2)", "Le 3ème est offert");
  - Ticket E.Leclerc: `fEstVisiblePictoPromoTEL`, `sTexteLogoTel` ("Recevez 34% en Ticket E.Leclerc").

## Cart

- Read: cart widget of `GET /magasin-…/recherche.aspx` (without a term, the lightest page, ≈ 140 KB).
  Lines `lstProduits[]` (`iQuantitePanier`, `rTotalAPayer`), total `sTotalAPayer` ("6,43 €").
- Change: `POST /magasin-…/panier.aspx?op=1`, body `d=<encoded JSON>`:
  `{"eTypeAction":1|2,"iIdProduit":"7459","iQuantite":3,"sNoPointLivraison":"<noPL>"}`.
  `iQuantite` is the **final quantity**; `eTypeAction` 1 increases, 2 decreases or removes (0). The direction is
  chosen from the current quantity (cart read again, or read less than 15 s ago). Response: a JSON array of
  events, only validated; confirmation is done by reading the cart back.
- `objContexteProvenanceArticle` (analytics context) is optional.

## Product page

- `GET /magasin-…/fiche-produits-<id>-produit.aspx` (cosmetic label). Unknown identifier: HTTP 200, store page
  without the product widget.
- `objProduit.sComposition` ("Ingrédients : …", lines separated by `\r`), `sAllergenes`
  ("Contient : … \r Traces de : …"), `lstMentionProduit[]` with `sTypeMention: ORIG` for the origin (raw
  products). The bulky blocks (`lstOperationTrade`, stickers) are removed from the fixtures.

## Order conditions (read-only)

- Current cart: `sDateProchainRetraitDisponible` ("Lundi 26 octobre à 07h00") = next pickup slot.
- Page global `"dateRetrait":"Lundi 26 octobre 07h00"`: date attached to the cart, not guaranteed as a booking.
- The `choix-horaire.aspx` grid shows a login with hCaptcha outside an authenticated session: not read.
- Minimum order: absent from logged-out pages (`minimumOrders: null`, check at checkout).
- `SaisirDateRetrait`, `ChangerDateRetrait`, `panier.aspx?op=7|11` change the pickup date: **never called**.

## Store search

JSON API `https://api-recherchemagasins.leclercdrive.fr/API_RechercheMagasins/api/v1`, called from a
`www.leclercdrive.fr` tab (CORS allowed):

1. `GET /autocomplete?search=<postcode|town>&provider=Woosmap` → `postalCodes[0].id`
2. `GET /autocomplete/coordinates?id=<id>&provider=Woosmap` → `{latitude, longitude}`
3. `GET /MapPoint/nearby?latitude=…&longitude=…&postalCode=…` → `points[]`: `noPL`, `noPR`, `name`,
   `serviceType` (`drive`, `relais`, `livraison`), `distance` (km), `urlSiteCourse` (shopping host).

The identifier exposed to the agent is `noPL` for a drive, `noPL-noPR` for a walk-in pickup point.
